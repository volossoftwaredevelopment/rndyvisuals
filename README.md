# rndyvisuals — сайт-портфолио Ивана Руди

Одностраничный кинематографичный сайт видеографа **Ivan Rudy (rndyvisuals)** — яхты, регаты, открытое море, Греция.

- **Сайт:** https://55kt.github.io/rndyvisuals/
- **Админка:** https://55kt.github.io/rndyvisuals/admin.html (скрытая, ссылок с сайта на неё нет)

**Стек:** Vite + чистый TypeScript (без фреймворков), GSAP + ScrollTrigger (анимации), Lenis (плавный скролл), SplitType (анимация текста). Шрифты Archivo и Space Grotesk — self-hosted через Fontsource. Хостинг — GitHub Pages, деплой через GitHub Actions.

---

## Структура проекта

```
index.html                  — сама страница (вся разметка секций)
admin.html                  — админка для управления видео
docs/DESIGN_SPEC.md         — полная дизайн-спецификация (источник правды)
src/
  site.config.ts            — константы: владелец репо, ссылки, соцсети
  data/videos.json          — манифест видео (ЕДИНСТВЕННЫЙ источник списка работ)
  styles/                   — токены палитры, база, компоненты
  modules/                  — прелоадер, курсор, анимации, оверлей-плеер и т.д.
  admin/                    — логика и стили админки
public/                     — копируется в сборку как есть (favicon, 404, robots)
.github/workflows/deploy.yml — автодеплой на GitHub Pages
```

## Как управлять видео (главное!)

Список работ на сайте целиком берётся из `src/data/videos.json`. Менять его можно двумя способами.

### Способ 1 — через админку (для Ивана, без кода)

Открой **https://55kt.github.io/rndyvisuals/admin.html**

**Шаг 0 — один раз: создать токен GitHub.** Токен — это «ключ», которым админка сохраняет изменения в репозиторий.

1. Зайди на GitHub под аккаунтом-владельцем репозитория и открой
   **github.com/settings/personal-access-tokens** → **Generate new token** (Fine-grained).
2. Название — любое, например `rndyvisuals-admin`. Срок — максимум (потом можно продлить).
3. **Repository access** → *Only select repositories* → выбери **55kt/rndyvisuals** (и только его).
4. **Permissions → Repository permissions:**
   - **Contents — Read and write** (чтобы сохранять список видео)
   - **Actions — Read-only** (чтобы админка показывала статус публикации)
5. Generate token → скопируй строку, начинающуюся с `github_pat_…`.

Токен никому не пересылай и нигде не публикуй — он даёт право менять сайт.

**Дальше — обычная работа:**

1. Вставь токен в поле сверху админки. Точка статуса станет бирюзовой — токен принят (он сохранится в браузере, вводить каждый раз не нужно).
2. **Добавить видео:** вставь ссылку на YouTube или Vimeo — название подтянется само, поправь клиента/категорию/длительность, если нужно.
3. **Поменять порядок:** перетащи строки за ручку ⋮⋮ — порядок в списке = порядок на сайте.
4. **Удалить:** крестик × у строки.
5. Нажми **Publish**. Админка закоммитит изменения, GitHub Actions пересоберёт сайт — примерно через **2 минуты** обновления появятся на сайте (статус видно прямо в админке: queued → building → live).

### Способ 2 — вручную через `src/data/videos.json`

Файл выглядит так: `{ "videos": [ …записи… ] }`. **Порядок записей в массиве = порядок на сайте.** Поля каждой записи:

| Поле | Что это |
|---|---|
| `id` | уникальный слаг латиницей через дефис, например `aegean-crossing` (используется в адресе оверлея) |
| `title` | название фильма, как оно выводится в списке работ |
| `client` | заказчик / судно, например `S/Y Mythos` или `Personal` |
| `category` | категория: `Yacht Film`, `Regatta Film`, `Charter Promo`, `Drone Study`, `Delivery Film`, `Short Film`… |
| `year` | год, число — `2025` |
| `duration` | длительность строкой — `1:24` |
| `source.type` | откуда видео: `youtube`, `vimeo`, `file` или `placeholder` (заглушка без видео) |
| `source.id` | id ролика для youtube/vimeo (см. пример ниже) |
| `source.url` | путь к файлу — только для `type: "file"` |
| `poster` | путь к своей обложке; **пустая строка = автоматически** (для YouTube — кадр с YouTube, иначе фирменный градиент) |
| `featured` | `true` — попадает в секцию Showreel (играет первый featured в списке) |

Пример записи с YouTube. `source.id` — это кусок после `watch?v=` в адресе: для `https://www.youtube.com/watch?v=AbCdEf12345` (или `https://youtu.be/AbCdEf12345`) id будет `AbCdEf12345`:

```json
{
  "id": "aegean-crossing",
  "title": "Aegean Crossing",
  "client": "S/Y Mythos",
  "category": "Yacht Film",
  "year": 2025,
  "duration": "1:24",
  "source": { "type": "youtube", "id": "AbCdEf12345" },
  "poster": "",
  "featured": true
}
```

После правки — закоммить и запушь в `main`, дальше всё произойдёт само (см. «Деплой»).

## Как заменить hero-фон на реальное видео

Сейчас на первом экране — градиентная заглушка. Чтобы поставить настоящее видео:

1. Сожми ролик: **до ~2.5 МБ, 1280×720, H.264 (CRF ~28), без звука**, 10–20 секунд луп. Например:
   `ffmpeg -i input.mov -an -vf scale=1280:720 -c:v libx264 -crf 28 -movflags +faststart public/hero.mp4`
2. Положи файл `hero.mp4` в `public/` (папка `public/` попадает в сборку как есть) — слот в `index.html` ждёт его именно по этому пути (`./hero.mp4`).
3. Открой `index.html`, найди в секции hero **закомментированный слот `<video>`** (ищи `hero__video`) и раскомментируй его. В слоте также прописан `poster="./hero-poster.jpg"` — кадр-обложка, который виден до загрузки видео: либо положи свой кадр в `public/hero-poster.jpg`, либо просто удали атрибут `poster`.
4. Закоммить и запушь — сайт обновится.

## Деплой

Полностью автоматический: **push в ветку `main` → GitHub Actions собирает проект → выкладывает на GitHub Pages** (`.github/workflows/deploy.yml`). Прогресс — во вкладке **Actions** репозитория, обычно ~2 минуты.

Один раз при настройке репозитория: **Settings → Pages → Source: GitHub Actions.**

## Миграция на кастомный домен

Когда появится домен (например `rndyvisuals.com`):

1. Создай файл `public/CNAME` с одной строкой — доменом:
   ```
   rndyvisuals.com
   ```
2. У регистратора домена добавь DNS-запись **CNAME → `55kt.github.io`** (для apex-домена без `www` некоторые регистраторы требуют A/ALIAS-записи — см. доку GitHub Pages).
3. В репозитории: **Settings → Pages → Custom domain** → введи домен → дождись проверки → включи **Enforce HTTPS**.
4. В коде поменяй на новый адрес: `liveUrl` в `src/site.config.ts`, `og:url` в `index.html` и ссылку «Back to harbor» в `public/404.html` (там абсолютный URL — относительный на странице 404 зацикливался бы). Запушь.

Больше ничего трогать не нужно: сборка использует `base: './'` (все пути относительные), поэтому тот же билд одинаково работает и на `55kt.github.io/rndyvisuals/`, и на собственном домене.

## Передача репозитория Ивану

Когда Иван заведёт свой GitHub-аккаунт:

1. **Settings → General → Danger Zone → Transfer ownership** → указать аккаунт Ивана.
2. GitHub Pages и Actions переезжают вместе с репозиторием автоматически — сайт продолжит собираться (адрес github.io сменится на `<иван>.github.io/rndyvisuals/`).
3. В коде поменять `owner` (и `liveUrl`, если сайт ещё на github.io-адресе) в `src/site.config.ts` — иначе админка будет коммитить не туда.
4. Иван создаёт **свой** токен по инструкции из раздела про админку (старый токен привязан к старому владельцу) и вставляет его в админку.
